03 / FIRST REQUEST

Send a reading.
Follow the response.

Register or select a vehicle, save its own limits, then send repeated readings. Sustained conditions show a pending timer before an alert becomes active.

01
Check readinessGET /health/ready

Telemetry checks its Vehicle Service dependency here. `UP` means it is ready to receive requests.

02
Post repeated readingsPOST /telemetry

Every reading is validated and checked against the registered vehicle. The demo simulator repeats synthetic samples every three seconds.

03
Evaluate each readingPOST /alerts/evaluate

Alert Service reads that vehicle's saved thresholds. It reports pending time, active alerts, and cleared alerts after recovery.

>_POWERSHELL / SAMPLE FLOW
$reading = @{
  vehicle_id = "VW-1001"
  speed = 150
  rpm = 3200
  battery_temperature = 38.5
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8002/telemetry" `
  -Method Post -ContentType "application/json" -Body $reading

Invoke-RestMethod -Uri "http://127.0.0.1:8003/alerts/evaluate" `
  -Method Post -ContentType "application/json" -Body $reading
EXPECT 201, THEN AN EVALUATION RESULTUSE COMPOSE/MANUAL PORTS IN THIS EXAMPLE
201
Telemetry accepted

Vehicle exists and values passed validation. The reading is stored in memory.

422
Invalid reading

One or more submitted values violate the request model’s constraints.

503
Dependency unavailable

Vehicle Service is unreachable or did not confirm the vehicle ID.

Important: The dashboard sends the same sample to Telemetry and Alert Service as two API calls. The simulator uses synthetic data only; no vehicle hardware is connected. If a service restarts, its in-memory records are lost.

OPERATOR NOTE / 04A

UP is not the whole story.

Liveness says a process responds. Readiness says it can accept work. Telemetry readiness also checks Vehicle Service, so it can be live but not ready.

05 / OPERATIONS

When something
doesn’t look right.

A short checklist for common first-run problems. Run commands from the repository root unless noted.

10048Address already in usePort is occupied+

A service is already listening on that port. Check whether a previous instance is still running before starting another copy:

Get-NetTCPConnection -LocalPort 8001,8002,8003 -State Listen

Stop the existing Uvicorn terminal with Ctrl + C, or choose another host port.

503Telemetry cannot reach Vehicle ServiceCheck the dependency URL+

In local Python mode, set the environment variable before starting Telemetry:

$env:VEHICLE_SERVICE_URL = "http://127.0.0.1:8001"

In Compose, Telemetry uses the internal service hostname `vehicle-service:8000` automatically.

DOWNA service is live but not readyInspect dependencies+

Check that the Vehicle API responds at http://127.0.0.1:8001/health/live and that Telemetry has the correct `VEHICLE_SERVICE_URL`. Readiness is dependency-aware; liveness intentionally is not.

LOGSInspect container outputCompose logs+
docker compose ps
docker compose logs -f --tail=100 telemetry-service
docker compose logs -f alert-service
RESETRestart or clear local monitoring dataUse with care+
docker compose restart telemetry-service
docker compose down
# Destructive for local Grafana, Prometheus, and Loki volumes:
docker compose down -v

API business records are in process memory and are cleared when their service restarts.

07 / READ BEFORE DEPLOYING

Useful reference.
Not vehicle control.

The project demonstrates service boundaries and observability patterns. It is deliberately not a production fleet platform or a certified automotive system.

01

Data is volatile

Vehicle, telemetry, and alert business data live in process memory. Restarting services clears it; there is no database, broker, or durable event delivery.

02

APIs are unauthenticated

Local Compose ports bind to loopback, but there is no user/device identity, authorization, or TLS. Do not expose these APIs publicly.

03

Alert delivery is not durable

The demo explicitly sends each reading to Alert Service, but it has no durable event pipeline, deduplication, paging integration, or incident lifecycle.

04

No hardware or safety case

No vehicle bus protocols, actuator commands, device provisioning, functional-safety analysis, certification, or regulatory approval is included.

05

Local observability has privileges

Alloy reads Docker container metadata through the local Docker socket. Treat that as privileged access and keep the stack on a trusted development host.

NEXT

What production would require

Threat and safety review, identity/access control, TLS, durable storage and delivery, HA/backup/recovery, image/dependency scanning, and operational ownership.
